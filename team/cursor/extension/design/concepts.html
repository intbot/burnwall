Three ways to show usage inside Cursor

Each concept puts the same backend data into the editor in a different way. A is a glance in the status bar, B is a detailed panel, C is coaching first, and D combines B and C.

Shows

  • Spend against your limit, always visible
  • The item changes colour as your pace rises: none, then amber, then red
  • On hover: projected month total, the date you'd reach your limit, and your biggest cost
  • An alert only when something changes (for example "you'll pass $200 this week")

Best for

  • The ~100 General users who spend $15 a month and only need a quiet warning
  • A fast first release: smallest build, nothing to learn

Trade-offs

  • The real hover card is Markdown, so the meter is drawn with text blocks (as shown), not a custom chart
  • No room to explain why. "Open details" needs a panel such as B or C

Shows

  • Month-to-date spend, projected total and the date you'd reach your limit
  • Spend so far against your limit, with the projection drawn to scale

Shows

  • Up to 3 changes ranked by money saved, each with the person's own evidence
  • One action per tip, for example copying a ready-made restart prompt
  • A "keep doing" section so it isn't only criticism
  • Your messages, targeted to everyone, a segment or one person

Best for

  • Changing habits at scale without one-to-one calls
  • The Approved Exceptions coaching plan, and General users heading past $200

Trade-offs

  • The most backend work: the habit checks and savings estimates have to be right
  • Tone matters, and you'd write or approve the wording
  • The extension can't open a new Cursor chat for the person, so it copies the prompt for them

Shows

  • Sidebar: where you stand, up to 3 tips, "keep doing", then "Show breakdown", your messages and model updates. This is the daily view
  • Editor tab: the full breakdown, opened from "Show breakdown", a tip or the status bar
  • Tips and data are linked: tip 1 is marked on the chat it's about and on the cache-read row, and tip 2 on the model
  • Where your money goes: tokens and cost by type, what the same tokens cost without -fast, and how to read it
  • How to compact: Cursor's own /summarize and @ → Chats, with the restart prompt as a fallback

Best for

  • Everyone: most people only need the sidebar
  • Raised-limit users and one-to-one conversations use the breakdown tab

Trade-offs

  • Two views to build (a sidebar view and an editor tab), but they share the same data and components
  • Backend work is the same as C. B adds no extra backend work
  • The token table needs per-model rates. Cursor's API doesn't list prices, so they're fitted from what your organization was charged

iShrink a long chat

  1. Same task, carrying on: type /summarize in that chat. Cursor compresses the earlier conversation into a summary, so later prompts re-send the summary instead of all 61 prompts.
  2. New task: start a new chat. If you need the old one, type @, choose Chats and pick it.
  3. Keep an eye on it: the context ring next to the chat input shows how full the chat is. Cursor only summarizes on its own when it's close to full, so summarize at about 20 prompts instead of waiting.
Summarizing reads the whole chat once, so it costs about one big prompt. It pays for itself within a few prompts.

True for all three

  • Data comes from the backend, which polls the Cursor Admin API. Numbers are a few minutes behind live, and the panel shows "updated X min ago".
  • Sign in once with your work account. Each person sees only their own usage, and admins see everyone.
  • The extension is read-only. It never changes limits or settings, and it can't see your chat content.
  • Combining them is natural: A's status bar item, with "Open details" opening a panel that has C's tips at the top and B's numbers below.
